# キーボード配置の読み込みとプレビュー

既存の単体編集を維持し、`配置` セグメントで `① キーボードを読み込む → ② ファイルを選ぶ → ③ 配置を選ぶ` のステップバーを表示します。①でファイル・リポジトリのルートフォルダのドロップ、ファイル / フォルダ選択、GitHub URL 読み込みを受け付け、複数の有効なファイルがある場合は②へ進みます。候補が1つなら自動読み込みして③へ進みます。③で物理レイアウト、配置先、キーキャップの割り当て、XY / 高さ / 回転補正を選びます。ステップバーから利用可能な段階に戻れます。新しい候補からファイルを選ぶまでは③へ進めず、失敗時は現在のキーキャップと適用済み配置を保持します。配置を含む project の復元後は③から再開します。

配置の読み込み後に3D表示領域の中央下へ現れる `キーキャップ単体` / `キーボード全体` で表示を切り替えます。左パネルが3D領域に重なるレイアウトでは、パネルの実効幅と列間の余白を除いた右側の空き領域の中央へ配置します。選択インジケーターは既存セグメントと同じアニメーションで移動し、reduced motion設定時は動かしません。キー位置は配置図、一覧、3D プレビューのクリックで選択できます。割り当て済みキーを編集するボタンは単体編集へ戻します。

ステップバーの DOM は配置パネル内の更新中も維持し、各丸の端から隣の丸の端までだけ接続線を描きます。現在のステップまで線のアクセントカラーが伸縮し、①から③へ直接進む場合は2本を順番に動かします。実施済みの丸とラベルにもアクセントカラーを使い、現在の丸はリングで区別します。③はキーキャップを割り当てたら実施済みとし、戻った場合も色を保持します。reduced motion設定時は線と内容を即時更新します。

物理レイアウト・配置先・キーキャップの select は設計セグメントと同じ `field` / `field-control--select` の構造とスタイルを使います。1u の換算基準は編集欄ではなく固定の読み出し値として表示します。

配置タブとキーキャップ一覧の配置図は同じ SVG を使い、固定の最小幅を設けずカードの内幅に合わせて縮小します。viewBox 内の配置全体を縦横比を維持して表示し、図内にスクロールバーを出しません。

## 入力形式

| 形式 | 読み込み対象 | 注意事項 |
| --- | --- | --- |
| QMK | `keyboard.json` / `info.json` の `layouts.*.layout` | `matrix` と XY は独立。親ディレクトリの定義は同時にドロップしたファイルまたは同じ GitHub リポジトリ内からマージする |
| QMK Configurator | `keyboard` / `layout` / `layers` を持つ JSON | 同じ入力集合に対象 keyboard の物理定義が必要。最初のレイヤーを位置ラベルに使う |
| KLE | JSON の行配列 | サイズ、stagger、回転中心、ISO Enter 等の補助矩形を保存。decal はキーとして配置しない |
| VIA / Vial | `layouts.keymap` を持つ定義 JSON | KLE と matrix 座標、layout option の組み合わせを扱う。候補が多い場合は選択する |
| ZMK | `.dtsi` / `.dts` / `.overlay` / `.keymap` の `keys` | `<&key_physical_attrs w h x y r rx ry>` の数値形式。include は入力集合から相対パスまたは一意な suffix で解決し、ノード override を統合する |
| RMK | `keyboard.toml` の `[layout].map` | 数値の matrix tuple、標準の幅指定と縦長 2u、custom shape、gap、row step、回転 cluster に対応。variant や未対応 stock shape は KLE / Vial への変換を案内する |
| KiCad | `.kicad_pcb` | Switch / MX / Choc の footprint または SW 番号の部品原点を取り付け中心とする。幅は 1u。Edge.Cuts の線・矩形・多角形・円を読み込む。ケースやスイッチ本体は再現しない |

座標のないキーマップは配線 matrix から推測せず、物理定義が必要な理由を表示します。ZMK のマクロ・式・条件コンパイルの評価、外部モジュールからの include 取得、FW のコンパイルは行いません。外部定義はまとめてドロップするか、展開済みの物理配置を指定してください。

## GitHub とローカル入力

- ローカル読み込みの入口は、左にファイル・右にフォルダを選ぶボタンを常時表示する。Lucide アイコン付きのアクセントカラーボタンを横並びの1つのグループにまとめ、中央の境界線で分ける。各ボタンから直接選択ダイアログを開き、ネイティブの file input は隠す。読み込んだ内容の形式・有効候補は自動判定する。
- 公開 GitHub のリポジトリ直下、`tree` フォルダ、`blob` ファイル、raw URL に対応する。default branch または URL の ref を解決し、commit SHA に固定して raw ファイルを取得する。
- ローカル・GitHubとも、候補ファイルを参照解決・解析してから一覧へ出す。物理座標のないキーマップ・ボード設定、不正な配置、未対応の定義は除外する。QMK の継承や ZMK include で物理座標を取得できるファイルは候補に残す。確認中は進捗を表示し、取得は最大4件並列で行う。
- ユーザーが確認済みの候補から読み込み対象を選ぶ。単一候補は自動読み込みし、同じファイル内の複数レイアウトは select で選択する。解析結果と参照ファイルは cache し、選択時の再取得を避ける。通信・権限・API 制限エラーは無効な配置と区別して表示する。
- 検索アイコン付きの検索欄と候補一覧は、フォント検索 UI と同じスタイルのカード内にまとめる。検索中も入力欄を維持し、候補が一致しない場合は空状態を表示する。
- 大きいリポジトリで Git Trees API の一覧が truncated の場合、フォルダ URL は該当 subtree を取得し直す。root URL の一覧が truncated の場合は絞り込みまたはドロップを案内する。
- 認証情報や token は送信しない。private repository や API 制限時はファイルのドロップを案内する。
- ファイルは 8 MiB 以下、キー数は 1000 以下、VIA option の組み合わせは 64 以下。座標と寸法は有限値を検証する。
- ローカルファイル、複数ファイル、リポジトリのルートフォルダのドロップに対応する。フォルダ内を再帰的に探索し、参照解決に必要な相対パスを維持する。`.git` / `.github` / `node_modules` / `vendor` / `target` / `dist` は探索せず、候補の除外規則は GitHub と揃える。深さ20階層、対応形式のファイル2000件を超える場合は小さいフォルダを案内する。KeycapMaker の project / 編集 JSON / font は既存経路で読み込む。

## プレビューと保存

プロジェクトのキーキャップ一覧には、初期状態で閉じた `配置先` の開閉欄と割り当て数を表示します。開くと配置タブと共通のキーボード配置図を表示し、そのキーキャップの取り付け位置をすべてアクセントカラーで強調します。他のキーキャップの位置は強調しません。配置図は確認専用で、クリックや開閉によって編集中のキーキャップや配置先を変えません。開閉状態はキーキャップごとにタブ移動や画面更新をまたいで保持し、別の project を読み込むと閉じた状態へ戻します。キーボードを読み込む前は位置欄を表示しません。

強調したキーにポインターを重ねると、割り当て先のラベル、XY / Z の位置、回転を確認できます。XY は読み込んだ配置の座標系を mm に換算したキー中心に位置補正を加えた値、Z は高さ補正、回転は配置の回転と回転補正の合計です。未割り当てのキーキャップは `未配置` と表示し、開いた配置図に強調位置はありません。

未割り当ての位置は半透明のガイドとして表示します。割り当てたキーキャップは実際の OpenSCAD preview mesh を用い、寸法を自動変更しません。モデルは編集パラメータごとに cache し、同じキーキャップを複数位置に使っても再生成しません。単体と全体のカメラ状態は独立して保持し、全体プレビューを単体サムネイルへ保存しません。

FW / KLE の配置に PCB 外形がない場合、ガイド面を表示します。これは製造用の基板・ケース形状ではありません。キーボード全体の mesh は preview 専用で、個別の STL / STEP / 3MF の出力を変えません。

正規化した配置と割り当てを [project manifest](project-data.md) 内へ保存します。キーキャップを削除したときは、その割り当ても除去します。
